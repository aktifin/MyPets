# 好友与共同照料

## 目标

本批次建立首个多人养宠闭环：

```text
发送好友申请
→ 接受好友关系
→ 设置宠物可见范围
→ 邀请好友成为 caregiver 或 viewer
→ 对方接受
→ 共享宠物进入对方宠物列表
→ caregiver 在主人授权后远程照料
```

好友、屏蔽、宠物隐私、共同照料关系和远程照料结果均由服务端判定。

## 一、好友接口

```text
POST /api/v1/friend-requests
GET  /api/v1/friend-requests
POST /api/v1/friend-requests/{id}/accept
POST /api/v1/friend-requests/{id}/reject
POST /api/v1/friend-requests/{id}/cancel

GET    /api/v1/friends
DELETE /api/v1/friends/{account_id}
```

首版使用精确用户名发送申请。

约束：

- 不能添加自己；
- 已是好友不能重复申请；
- 双方存在待处理申请时不能再创建；
- 任一方屏蔽对方后不能创建或接受好友申请；
- 只有接收方可接受或拒绝；
- 只有发送方可取消。

## 二、屏蔽

```text
POST   /api/v1/blocks
GET    /api/v1/blocks
DELETE /api/v1/blocks/{account_id}
```

屏蔽操作会：

- 解除现有好友关系；
- 取消双方待处理好友申请；
- 取消双方待处理共同照料邀请；
- 移除双方宠物上的 `caregiver` 和 `viewer` 关系；
- 向被移除关系的账户发送账户级 `pet_deleted` 事件，从本地缓存删除共享宠物。

解除屏蔽不会自动恢复好友或共同照料关系。

## 三、宠物隐私

```text
GET   /api/v1/pets/{pet_id}/privacy
PATCH /api/v1/pets/{pet_id}/privacy
```

可见范围：

```text
private      仅宠物关系成员可见
caregivers   照料者和关系成员可见
friends      好友可见
public       公开可见
```

独立开关：

```text
allow_remote_care
```

- `owner` 和 `co_owner` 可修改隐私；
- `caregiver` 只有开关启用后才能远程照料；
- `viewer` 永远不能照料；
- 开关关闭不会删除共同照料关系，只阻止业务操作。

好友宠物查询：

```text
GET /api/v1/friends/{account_id}/pets
```

只返回有限公开字段，不包含私人提醒、消息、设备信息、详细健康历史或 AI 记忆。

## 四、共同照料邀请

```text
POST /api/v1/pets/{pet_id}/caregiver-invitations
GET  /api/v1/caregiver-invitations
POST /api/v1/caregiver-invitations/{id}/accept
POST /api/v1/caregiver-invitations/{id}/reject
POST /api/v1/caregiver-invitations/{id}/cancel
```

首版可邀请角色：

```text
caregiver
viewer
```

约束：

- 只有 `owner` 或 `co_owner` 可以邀请；
- 只能邀请现有好友；
- 不能邀请已拥有宠物关系的账户；
- 屏蔽状态下不能创建或接受邀请；
- 接受邀请时好友关系必须仍然存在；
- 接受后生成正式 `AccountPetRelation`；
- 邀请不会自动开启远程照料。

接受邀请后，服务端向被邀请账户发送 `pet_updated` 事件，PC 下一次同步后共享宠物进入宠物列表。

## 五、照料者管理

```text
GET    /api/v1/pets/{pet_id}/caregivers
DELETE /api/v1/pets/{pet_id}/caregivers/{account_id}
```

- `owner/co_owner` 可以移除照料者；
- `caregiver/viewer` 可以主动退出自己的共同照料关系；
- 不能通过该接口删除 `owner/co_owner`；
- 移除后发送账户级 `pet_deleted` 事件。

## 六、远程照料

远程照料复用现有接口：

```text
POST /api/v1/pets/{pet_id}/interactions/feed
POST /api/v1/pets/{pet_id}/interactions/play
POST /api/v1/pets/{pet_id}/interactions/clean
POST /api/v1/pets/{pet_id}/interactions/pet
POST /api/v1/pets/{pet_id}/interactions/rest
```

继续使用原有：

- 幂等键；
- 冷却时间；
- 每日上限；
- 服务端状态结算；
- 成长和羁绊规则；
- 活动记录；
- 跨账户宠物更新事件。

共同照料没有第二套成长或状态计算逻辑。

## 七、PC 界面

托盘新增：

```text
好友与共同照料…
```

界面支持：

- 精确用户名发送好友申请；
- 接受和拒绝好友申请；
- 查看和解除好友；
- 屏蔽与解除屏蔽；
- 修改当前宠物可见范围；
- 开关远程照料；
- 邀请好友成为 caregiver 或 viewer；
- 接受和拒绝共同照料邀请；
- 查看当前宠物照料者及贡献；
- 移除共同照料关系。

当前宠物不是本人 `owner/co_owner` 时，管理控件禁用。接受邀请后 PC 自动执行宠物同步，用户可从现有“切换宠物”菜单选择共享宠物，并通过现有宠物状态面板远程照料。

## 八、同步事件

本批新增或使用：

```text
friend_request_received
friend_request_updated
friendship_updated
account_block_updated
pet_privacy_updated
caregiver_invitation_received
caregiver_invitation_updated
pet_updated
pet_deleted
```

旧客户端会忽略未知社交事件但继续推进游标；共享宠物接入使用现有 `pet_updated`，关系移除使用现有 `pet_deleted`，因此现有桌面同步器无需新增社交缓存结构。

## 九、当前限制

- 没有用户名模糊搜索或推荐好友；
- 没有好友备注和分组；
- 没有共同照料贡献排行榜；
- 没有虚拟礼物；
- 没有小程序好友页面；
- 没有 WebSocket 即时推送；
- 好友和邀请列表在 PC 中按需读取，不做离线编辑；
- 数据库迁移框架仍未实现，新社交表依赖开发环境自动建表。
