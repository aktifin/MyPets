# MyPets 设备撤销执行与人工跟进

## 一、目标

版权存证撤销后，服务端会停止分发关联专属素材，并要求相关设备清理精确缓存、写入永久撤销标记、切换到安全兼容形象并提交设备回执。

本功能用于管理端确认各设备是否真正完成撤销执行，并对失败或长期未回执设备建立人工跟进闭环。

## 二、事实与运营状态分离

设备回执是客户端提交的原始事实，包括：

- 清理状态；
- 缓存是否删除；
- 安全兼容形象是否启用；
- 客户端处理时间；
- 重试次数；
- 设备返回的信息。

人工跟进不会修改设备回执。每次处理以新记录追加到 `pet_asset_revocation_follow_ups`，形成不可变历史。

支持的人工状态：

```text
investigating  处理中
resolved       已解决
waived         已豁免
```

没有人工记录时显示为 `unreviewed`。

## 三、统计口径

管理台按已撤销的 right 和关联专属 Release 形成撤销批次，并统计与目标宠物存在照料关系的所有未撤销设备。

设备原始状态：

- 已安全清理：回执为 `completed`，且 `cache_cleared=true`、`fallback_applied=true`；
- 清理失败：存在回执，但状态失败或两项安全检查未同时通过；
- 未回执：当前有效设备尚未提交该 right/Release 的回执。

需跟进规则：

- 失败或未回执且没有 `resolved/waived` 记录；
- 已进入 `investigating` 的设备，即使后续收到成功回执，也保留为待人工关闭；
- 最新状态为 `resolved` 或 `waived` 后不再计入需跟进。

“已安全清理”和“已解决/已豁免”分别统计，避免把人工结案误认为客户端技术执行成功。

## 四、管理台操作

入口：

```text
/admin
→ 版权与专属部署
→ 设备撤销执行与人工跟进
```

页面提供：

- 撤销批次数量；
- 应执行设备数；
- 已安全清理、失败、未回执和需跟进数量；
- 每个撤销批次的安全清理完成率；
- 设备、账户、平台、最近在线时间和回执详情；
- 全部、需跟进、未回执、失败、处理中、已解决和已豁免筛选；
- 单设备跟进记录和完整历史。

只有 `publisher` 和 `superadmin` 可以新增跟进记录。其他管理员可以只读查看聚合结果和历史。

## 五、接口

```text
GET  /api/v1/admin/governance/revocation-operations
POST /api/v1/admin/governance/revocation-follow-ups
GET  /api/v1/admin/governance/revocation-follow-ups
```

聚合接口支持：

```text
right_id
attention_only
limit
```

人工跟进目标由 `right_id + release_id + device_id` 唯一定位，因此既可以处理已有失败回执的设备，也可以处理从未提交回执的设备。

## 六、审计

每次新增跟进记录都会写入管理员审计日志：

```text
pet_asset_revocation.follow_up_recorded
```

审计内容包括 right、Release、设备、可选回执、处理状态和说明。

## 七、运维边界

- 已撤销设备不计入当前应执行设备；
- 撤销设备前应先确认其失败或未回执事项是否需要导出和结案；
- 人工豁免只能表示运营层面不再追踪，不会恢复素材分发，也不会删除本地撤销要求；
- 版权存证仍处于 `revoked`，客户端重新上线后仍会收到撤销清单并尝试清理；
- 回退 `004_revocation_follow_up` 会删除全部人工跟进历史，但保留客户端回执。
