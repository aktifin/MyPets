# 消息分类与休眠恢复提醒

## 消息分类

桌面消息仍使用现有会话、消息、回执、同步事件和 WebSocket 游标通知链路。本阶段没有新增第二套消息存储。

服务端返回的会话增加：

- `category`
- `category_label`

支持的分类：

| category | 显示名称 | 产生方式 |
|---|---|---|
| `direct` | 普通私聊 | 不使用宠物身份发送的文本消息 |
| `friend_pet` | 好友宠物 | 使用 `sender_pet_id` 发送的文本消息 |
| `visit` | 串门留言 | 串门申请中的留言投影为 `visit_message` |
| `shared_care` | 共同照料 | 共同照料邀请投影为 `care_event` |
| `growth` | 成长通知 | 成长等级、羁绊等级或成长阶段变化投影为 `growth_notice` |

当前分类由会话的最新消息决定。好友之间继续复用唯一私聊会话，因此后续普通文本可以把该会话重新归入普通私聊或好友宠物分类。

### 领域事件投影

`GET /api/v1/conversations` 会先对当前账户最近的可投影同步事件做幂等物化，再返回会话列表。

投影不会修改源业务记录：

- 串门状态仍以 `pet_visits` 为准；
- 共同照料仍以邀请和关系表为准；
- 成长仍以宠物权威状态和成长事件为准；
- 分类消息只是用户可读的折叠视图。

每个领域事件使用稳定幂等键。重复刷新、实时重连或多设备读取不会重复创建消息。

成长通知使用账户自己的只读系统会话。它会产生未读计数，但不能由客户端发送内容。

## 桌面消息抽屉

桌面端支持按以下分类筛选：

- 全部分类
- 普通私聊
- 好友宠物
- 串门留言
- 共同照料
- 成长通知

系统会话只读。消息抽屉不会因新消息自动弹出；仍由托盘菜单或宠物消息徽标显式打开。

本地 SQLite 缓存增加 `category` 和 `category_label`。旧缓存启动时通过窄范围 `ALTER TABLE` 自动补列；缓存仍可删除后从服务端重建。

## 休眠恢复提醒

提醒调度器记录运行期间的上次扫描时间。下次扫描间隔超过恢复阈值，且期间确有提醒到期时，判定为休眠或系统暂停恢复。

恢复流程：

```text
长时间未扫描
→ 扫描到多条到期提醒
→ 每条提醒分别标记本机已投递
→ 每条投递操作继续同步云端
→ 桌面只显示一张恢复摘要
→ 用户点击“逐条处理”后再进入原有完成/贪睡流程
```

冷启动时已经逾期的提醒仍按普通折叠提醒处理，不会误报为系统刚从休眠恢复。

恢复摘要最多预览前三条标题，并显示：

- 错过提醒数量；
- 最早和最晚到期时间；
- 估算的系统暂停时长。

摘要不会自动完成、忽略或贪睡任何提醒。

## 宠物外出时的提醒

宠物串门外出时，主宠物窗口会隐藏。提醒卡因此改为独立工具窗口，并优先定位在外出胶囊旁边。

提醒模块不会读取：

- 访客宠物窗口数据；
- 好友消息正文；
- 串门场景私有数据；
- 本机聊天记忆。

宠物外出不影响提醒的本地到点投递、离线队列和云端状态同步。

## 当前限制

- 领域事件投影仅扫描最近 500 条相关事件；
- 会话分类不是用户自定义标签；
- 当前没有独立的消息分类管理页面；
- 恢复判断基于扫描时间间隔，不读取操作系统电源事件；
- 恢复摘要只在桌面端实现，Web 门户尚未提供同等界面。
