# 访客宠物桌面与双宠互动

## 目标

本批次补全异步串门在 Windows 桌面的实际展示：接待宠物保持原桌面窗口，好友来访宠物使用独立 `GuestPetWindow`，双方可执行有限、服务端确认的双宠动作。

```text
串门被接受
→ PC 实时游标刷新
→ 获取串门场景公开字段
→ 解析访客形象身份
→ 使用缓存或已发布素材包
→ GuestPetWindow 固定显示在接待宠物旁
→ 服务端确认互动
→ 双方同步播放动作
```

## 服务端接口

### 获取桌面场景

```text
GET /api/v1/visits/{visit_id}/scene
```

仅串门双方账户可访问。返回字段包括：

- 申请人与接待人公开账户摘要；
- 来访宠物和接待宠物名称、位置、成长阶段、等级与心情；
- `template_id`、`template_version`、`identity_version` 和 `asset_version`；
- 性格类型；
- 串门留言、开始时间和预计返家时间；
- 当前账户是否可以互动或发送访客返家。

该接口不返回：

- 私人提醒；
- 消息正文或聊天记忆；
- 设备信息；
- 饥饿、健康、清洁等详细日常数值；
- 好友列表或其他宠物资料。

### 双宠互动

```text
POST /api/v1/visits/{visit_id}/interactions/greet
POST /api/v1/visits/{visit_id}/interactions/wave
POST /api/v1/visits/{visit_id}/interactions/play
POST /api/v1/visits/{visit_id}/interactions/sit_together
```

请求体：

```json
{
  "idempotency_key": "desktop-visit-wave-<uuid>"
}
```

规则：

- 只有接待方可以从桌面触发；
- 串门必须处于 `active`；
- 同一幂等键不会重复生成互动；
- 互动结果分别写入双方账户事件流；
- 不增加成长经验、羁绊经验或照料贡献；
- 不修改饥饿、精力、心情、清洁和健康等服务端数值。

事件类型：

```text
pet_visit_interaction
```

## GuestPetWindow

访客窗口是独立的无边框透明工具窗口，只有以下能力：

- 显示访客名称和主人名称；
- 加载已验证的宠物素材包；
- 缺少精确素材时使用安全兼容形象；
- 后台下载精确已发布素材包后热切换；
- 打招呼；
- 挥挥爪；
- 一起玩；
- 并排坐下；
- 接待方发送访客提前返家；
- 拖动窗口位置。

访客窗口没有入口读取：

- 本机消息抽屉；
- MyReminder；
- 宠物照料面板；
- 云端账户设置；
- 好友和屏蔽管理；
- 本地 SQLite 私人数据。

动作采用“服务端确认后播放”规则。点击菜单只提交请求，只有收到成功响应后，主宠物和访客宠物才同步播放动作。

## 场景站位

`DualPetSceneCoordinator` 将访客优先放在接待宠物右侧；空间不足时切换到左侧，并始终限制在当前屏幕工作区内。

普通状态使用标准间距；`play` 和 `sit_together` 临时缩短间距，动作结束后恢复固定站位。应用每 500 毫秒重新校正一次位置，接待宠物移动后访客会跟随到合理位置。

当前只显示与“当前选择的接待宠物”对应的一只访客。切换到其他宠物后，旧访客窗口关闭；切回对应接待宠物时，根据服务端活动串门重新建立。

## 主宠物外出

当前选择的宠物作为来访方外出时：

- 主宠物窗口隐藏；
- 自主跑动暂停；
- 显示低打扰 `AwayIndicator`；
- 显示接待人和预计返家倒计时；
- 可以提前召回；
- 到期或召回后恢复进入外出前的显示和暂停状态。

如果用户在外出前已经手动隐藏或暂停宠物，返家后不会擅自改变该状态。

## 素材安全

访客形象继续复用既有素材交付链：

```text
服务端场景公开形象版本
→ PetAssetCatalog 精确查找
→ 缓存或内置包
→ 不匹配时查询公开发布目录
→ 校验 ZIP 大小与 SHA-256
→ 拒绝路径逃逸、符号链接和加密文件
→ 原子安装
```

素材包仍是纯数据，不执行脚本或插件。

## 当前限制

- 每个接待宠物同一时间只显示一只来访宠物；
- 双宠动作使用现有素材动作映射，没有专用双宠骨骼或碰撞动画；
- 互动事件目前不展示历史列表；
- 访客位置是桌面客户端本地布局，不跨设备同步；
- 未实现三只以上宠物聚会；
- 未实现互动礼物、照片或成长奖励。
