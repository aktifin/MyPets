# MyPets PC 本地状态仓库

## 定位

`LocalStateStore` 是 PC 客户端的 SQLite 缓存与离线队列，不是云端权威数据库。

它解决以下问题：

- 一个账户在本机缓存多只宠物；
- 记录本设备当前显示的宠物；
- 保存共同照料关系的本地快照；
- 持久化折叠消息和提醒实例；
- 应用重启后恢复未完成提醒；
- 断网时保存待上传语义事件；
- 保存增量同步和 WebSocket 事件游标。

宠物成长、权限、串门和好友关系最终仍由服务端判定。客户端缓存不能覆盖更新的服务端状态。

## 文件位置

数据库默认保存到：

```text
%LOCALAPPDATA%/OnePicDesktopPet/state.sqlite3
```

非 Windows 环境或未设置 `LOCALAPPDATA` 时使用：

```text
~/.desktop_pet/OnePicDesktopPet/state.sqlite3
```

设置文件和数据库共用 `config.user_data_dir()`，避免同一应用在不同模块中产生多个数据根目录。

## 数据表

### `pets`

保存宠物实例缓存，包括：

- 稳定 `pet_id`；
- 模板、视觉身份和素材版本；
- 成长阶段与等级；
- 饱食、精力、心情、清洁和健康；
- 在家、串门、聚会和返家状态；
- 服务端状态版本。

### `account_pet_relations`

保存账户与宠物的本地关系快照：

```text
owner
co_owner
caregiver
viewer
```

删除宠物缓存时，关系通过外键级联删除。

### `device_state`

保存本设备选择，例如：

```text
active_pet_id
```

当前宠物属于设备状态，不应直接同步成所有设备共同选择。

### `folded_notifications`

统一保存低打扰通知，但消息和提醒仍通过 `kind` 分别计数：

```text
message
reminder
visit
growth
system
```

查看消息不能自动完成提醒；归档会同时标记已读。

### `reminder_occurrences`

保存具体提醒实例，而不是只保存重复规则。

客户端只查询 `PENDING` 且已经到期的实例。相同 `occurrence_id` 采用版本号覆盖，旧版本不得覆盖新版本。

### `cloud_outbox`

保存断网期间待上传的语义事件。

每条事件必须具有：

- 唯一 `event_id`；
- 唯一 `idempotency_key`；
- `sequence_number`；
- 带时区创建时间；
- JSON 业务载荷。

服务端确认后才从 outbox 删除。

### `cloud_cursors`

保存不同同步流的最后序号。游标只能增加，较旧响应不能回退本地游标。

## 时间规范

所有需要排序或比较的时间在写入 SQLite 前统一转换为 UTC，并使用带 `+00:00` 的 ISO 8601 字符串。

这样可以避免以下错误：

```text
2026-07-24T17:00:00+09:00
2026-07-24T08:00:00+00:00
```

两者表示同一时刻，但未经 UTC 归一化时不能安全使用字符串排序。

领域对象仍可保留原始时区名称，例如提醒的 `timezone = Asia/Tokyo`，用于界面展示和重复规则计算。

## 首次启动兼容

当前公开版本只有一套本地素材。首次启动时 `PetRegistry` 创建一个兼容实例：

```text
pet_id: local-default-pet
template_id: local.default
owner: local-account
```

该实例只为现有单机用户提供平滑迁移。正式账户登录后，云端宠物同步可以替换本地默认资料，但不能静默删除用户数据。

当前窗口仍使用现有单套素材。注册表已经稳定宠物身份和当前选择，后续版本再按模板和素材版本加载不同宠物资源包。

## 应用生命周期

启动：

```text
加载 JSON 设备设置
→ 打开 SQLite
→ 执行幂等建表
→ 恢复或创建当前宠物
→ 创建 PetWindow
```

退出：

```text
保存窗口和边缘状态
→ 关闭 SQLite
→ 隐藏托盘
→ 关闭窗口
```

`close()` 为幂等操作，避免重复退出信号导致二次关闭异常。

## 并发约束

当前 SQLite 连接属于 Qt 主线程。后续网络同步不得直接从工作线程复用该连接。

可选实现方式：

1. 网络线程通过 Qt Signal 把写入请求投递到主线程；
2. 每个工作线程创建独立连接；
3. 把数据库访问集中到专用串行工作线程。

任何方式都必须保持单个业务事务原子提交。

## 隐私边界

本地数据库可能包含提醒正文和消息正文，因此：

- 不提交到 Git；
- 不打包进发布版本；
- 不上传原始语音；
- 不保存模型 API 密钥；
- 不允许访客宠物读取；
- 日志不得直接打印完整私密正文。

后续账户退出应提供“保留本地缓存”和“清除本机数据”两个明确选项。

## 迁移规则

当前 `SCHEMA_VERSION = 1`。

后续修改结构时必须：

1. 新增显式迁移步骤；
2. 在事务中执行；
3. 迁移前保留可恢复备份；
4. 不通过删除数据库逃避迁移；
5. 为旧版本数据库增加回归测试。

## 测试覆盖

当前测试覆盖：

- 多宠物写入和当前宠物恢复；
- 默认本地宠物只创建一次；
- 账户宠物关系；
- 消息和提醒未读数分离；
- 无时区时间拒绝；
- 提醒版本防回退；
- 跨时区到期比较；
- outbox 幂等；
- 同步游标单调递增。
