# 用户宠物原图提交与审核

## 目的

该功能用于接收用户为本人宠物提交的静态参考图片，并将通过审核的图片送入后续人工素材制作队列。

它不是自动宠物生成器，也不会在审核通过后直接替换宠物形象、生成动作帧或发布素材包。

## 权限边界

- 只有宠物的 `owner` 或 `co_owner` 可以提交原图。
- 用户只能查看和下载本人提交的图片。
- 管理员列表和图片预览需要管理员账户令牌。
- 管理员 `edit` 权限负责领取待处理提交。
- 管理员 `review` 权限负责通过或驳回审核中的提交。
- 管理员操作写入 `admin_audit_logs`。

## 状态机

```text
pending_processing
        |
        | start-review
        v
    in_review
      /    \
 approve  reject
   v        v
approved  rejected
```

当前终态 `approved` 仅表示：

- 图片主体和提交信息适合进入人工制作队列；
- 权利声明已被记录；
- 后续仍需制作、素材包校验、视觉身份检查和发布审核。

响应中的 `publication_ready` 固定为 `false`，用于防止客户端把原图审核通过误解为可直接发布。

## 用户 API

### 创建提交

`POST /api/v1/pet-asset-submissions`

请求类型：`multipart/form-data`

必填请求头：

```text
Idempotency-Key: portal-asset-submission-...
```

表单字段：

| 字段 | 说明 |
|---|---|
| `pet_id` | 本人拥有或共同拥有的宠物 ID |
| `style_preference` | `original`、`light_chibi` 或 `full_chibi` |
| `personality_hint` | 可选，最多 240 字的性格或识别提示 |
| `rights_basis` | `owner_photo` 或 `authorized_use` |
| `rights_confirmed` | 必须为 `true` |
| `image` | 单帧 JPEG、PNG 或 WebP |

相同幂等键重试会返回最初创建的提交。相同账户、宠物和清理后图片哈希已有待处理、审核中或已通过记录时，会拒绝重复提交。

### 查询

- `GET /api/v1/pet-asset-submissions`
- `GET /api/v1/pet-asset-submissions/{submission_id}`
- `GET /api/v1/pet-asset-submissions/{submission_id}/image`

列表支持 `status` 过滤。图片下载要求账户鉴权，并返回 `Cache-Control: private, no-store`。

## 管理员 API

- `GET /api/v1/admin/pet-asset-submissions`
- `GET /api/v1/admin/pet-asset-submissions/{submission_id}`
- `GET /api/v1/admin/pet-asset-submissions/{submission_id}/image`
- `POST /api/v1/admin/pet-asset-submissions/{submission_id}/start-review`
- `POST /api/v1/admin/pet-asset-submissions/{submission_id}/approve`
- `POST /api/v1/admin/pet-asset-submissions/{submission_id}/reject`

管理员列表支持 `status`、`account_id`、`pet_id` 和 `limit` 过滤。

驳回必须提供至少 3 个字符的原因。审核结果通过 `pet_asset_submission_updated` 同步事件返回用户端。

## 图片安全处理

上传后不会直接保存用户提供的原始字节流。服务端执行：

1. 限制压缩文件大小和像素总量；
2. 使用 Pillow 实际解码图片；
3. 只接受 JPEG、PNG、WebP；
4. 拒绝动画图片和异常大图；
5. 校正 EXIF 方向；
6. 重新编码为 JPEG 或 PNG；
7. 不复制 EXIF、GPS、软件标识和其他原始元数据；
8. 对清理后的文件计算 SHA-256；
9. 写入受控对象存储路径。

SVG、脚本、ZIP 和其他非静态栅格内容不能通过图片解码检查。

默认限制：

- 输入和清理后文件最大 12 MiB；
- 最大约 4,194 万像素；
- 单边 64 至 8192 像素。

可通过以下环境变量调整：

- `MYPETS_MAX_PET_SUBMISSION_BYTES`
- `MYPETS_MAX_PET_SUBMISSION_PIXELS`

## 数据模型

表：`user_pet_asset_submissions`

关键字段：

- 账户和宠物归属；
- 状态与风格偏好；
- 权利依据和确认时间；
- 清理后的对象键、媒体类型、SHA-256、尺寸；
- 审核人、审核时间和审核意见。

开发环境通过 `Base.metadata.create_all` 创建缺失表。Alembic 环境已导入该模型，但仓库当前仍缺正式 revision 版本链；生产升级前必须补版本化 migration。

## 明确未实现

- 自动抠图；
- 自动生成动作序列；
- 自动生成 Spritesheet；
- 自动创建或发布素材包；
- 自动修改宠物 `identity_version` 或 `asset_version`；
- 无人工审核的生成式图像工作流；
- 视觉身份一致性评分和版权复核档案。

这些能力分别属于后续素材制作工单、专属素材部署，以及视觉身份与版权治理阶段。
