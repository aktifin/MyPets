# MyPets 实时通知与断线补偿

## 目标

本批次为 PC 和 `/portal` 用户 Web 端增加低耦合实时通知：

```text
服务端业务事务提交
→ append-only sync_events 游标增加
→ WebSocket 发现账户游标变化
→ 客户端收到 events_available
→ PC 拉取 /sync/events
→ Web 门户刷新对应权威 API
```

WebSocket 只负责降低通知延迟，不替代现有同步游标、业务 API、SQLite 缓存或服务端权限校验。

## 认证流程

普通账户令牌或设备令牌先请求：

```text
POST /api/v1/realtime/ticket
Authorization: Bearer <account-or-device-token>
```

响应包含短期票据、过期时间和协议名：

```json
{
  "ticket": "short-lived-signed-ticket",
  "expires_at": "2026-07-25T10:00:00Z",
  "protocol": "mypets.realtime.v1"
}
```

浏览器和 PC 使用 WebSocket 子协议头连接：

```text
mypets.realtime.v1
mypets.ticket.<ticket>
```

票据不会放入 URL 查询参数，避免进入常见访问日志、代理日志和浏览器历史。

默认票据有效期为 60 秒，只用于建立连接。设备令牌对应的设备在连接期间被撤销或凭据版本变化时，服务端关闭实时连接。

## WebSocket 地址

```text
WS  /api/v1/realtime/ws
WSS /api/v1/realtime/ws
```

服务端接受连接后发送：

```json
{
  "type": "hello",
  "cursor": 123,
  "server_time": "...",
  "source_kind": "account"
}
```

游标变化时发送：

```json
{
  "type": "events_available",
  "cursor": 124,
  "server_time": "..."
}
```

周期心跳：

```json
{
  "type": "heartbeat",
  "cursor": 124,
  "server_time": "..."
}
```

客户端可以返回：

```json
{
  "type": "ack",
  "cursor": 124
}
```

实时通道不会发送消息正文、好友资料、提醒正文、宠物详细状态或管理员数据。

## 服务端实现

服务端按账户检查 `sync_events` 的最大序号。默认每 1 秒检查一次，因此：

- 适用于当前模块化单体和开发阶段；
- 多进程实例只要共享数据库即可看到同一游标；
- 不依赖进程内事件总线，不会因请求落到不同 worker 而丢失通知；
- 事务回滚不会产生虚假业务正文推送；
- 生产规模扩大后可替换为 PostgreSQL LISTEN/NOTIFY、Redis Pub/Sub 或托管消息系统。

环境变量：

```text
MYPETS_REALTIME_TICKET_SECONDS=60
MYPETS_REALTIME_POLL_INTERVAL_SECONDS=1
MYPETS_REALTIME_HEARTBEAT_SECONDS=20
```

范围约束：

- 票据有效期：15～300 秒；
- 游标检查间隔：0.25～10 秒；
- 心跳间隔：5～120 秒。

## PC 行为

PC 在设备 bootstrap 完成后申请实时票据并建立 Qt WebSocket。

收到 `hello` 或 `events_available` 后：

1. 调用原有 `/api/v1/sync/events`；
2. 应用宠物、消息、提醒等增量事件；
3. 刷新好友与共同照料快照；
4. 刷新串门快照；
5. 对新好友申请、共同照料邀请和串门申请显示托盘通知。

连接异常时指数退避重试，最大 30 秒。原有定时轮询继续运行，因此 WebSocket 不可用不会造成数据永久丢失。

## Web 门户行为

Web 门户使用账户令牌申请票据。令牌仍只存于 `sessionStorage`。

收到游标提示后，页面以 250 毫秒防抖刷新：

- portal dashboard；
- 好友、申请、屏蔽和共同照料邀请；
- 异步串门列表与只读状态卡。

`hello` 也触发一次刷新，以关闭“初始 HTTP 请求完成后、WebSocket 建立前”这一时间窗口。

WebSocket 断开后页面继续可用，用户仍可使用现有刷新按钮。

## 安全边界

- 不在 URL 中传递账户令牌、设备令牌或实时票据；
- WebSocket 只返回账户级游标，不返回事件载荷；
- 业务数据仍由各 REST API 进行完整权限校验；
- 设备撤销在连接循环中持续检查；
- 页面脚本为同源静态资源，并继续使用 CSP、`no-store` 和 iframe 禁止策略；
- AI 不参与实时连接，不具备消息发送、提醒执行或设备控制能力。

## 当前限制

- 当前通过数据库短周期查询发现游标变化，不是数据库原生通知；
- 尚未实现每账户连接数量限制和独立实时限流；
- 尚未提供跨区域实时网关；
- WebSocket 不携带完整事件，首次加载与断线恢复仍依赖 REST；
- 正式公网部署需要 HTTPS/WSS、反向代理超时配置和连接监控。
