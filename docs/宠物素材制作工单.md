# 宠物素材制作工单

本文档说明用户宠物原图通过审核后，如何进入受控的人工素材制作流程。

## 业务边界

制作工单只负责：

- 关联已通过的用户原图提交；
- 记录目标宠物、负责人、进度和操作历史；
- 收集经安全清理的补充参考图；
- 校验制作完成的声明式素材 ZIP；
- 把产物标记为 `ready`，等待后续独立发布审核。

制作工单不会：

- 自动调用生成式图像服务；
- 自动生成动作帧；
- 自动创建公开 release；
- 自动切换公共 stable 通道；
- 自动修改宠物 `identity_version` 或 `asset_version`；
- 执行素材包中的脚本、插件或程序。

## 状态机

```text
queued
├─ processing
├─ needs_input
├─ failed
└─ cancelled

processing
├─ processing（更新进度）
├─ needs_input
├─ failed
├─ cancelled
└─ ready（仅通过产物上传进入）

needs_input
├─ processing
├─ failed
├─ cancelled
└─ ready（仅通过产物上传进入）

failed
├─ queued
├─ processing
└─ cancelled

ready / cancelled
└─ 终态
```

普通状态更新不能直接把工单设为 `ready`。只有素材包通过服务端校验后，工单才能进入 `ready`。

## 用户 API

```text
GET  /api/v1/pet-asset-production-jobs
GET  /api/v1/pet-asset-production-jobs/{job_id}
POST /api/v1/pet-asset-production-jobs/{job_id}/cancel
POST /api/v1/pet-asset-production-jobs/{job_id}/reference-images
GET  /api/v1/pet-asset-production-jobs/{job_id}/reference-images/{reference_id}/image
```

用户只能访问本人账户的工单。

用户可以：

- 查看工单状态、进度、负责人和公开操作记录；
- 在 `queued`、`processing` 或 `needs_input` 时补充参考图；
- 在 `queued` 时撤回尚未开始的工单。

用户不能：

- 分配管理员；
- 修改制作进度；
- 上传 ZIP 产物；
- 下载管理员暂存的 ZIP；
- 恢复已经取消的工单。

补充参考图使用与原图提交相同的安全处理：

- 实际解码 JPEG、PNG 或 WebP；
- 拒绝动画与伪装文件；
- 限制文件大小、宽高和总像素；
- 处理 EXIF 方向；
- 重新编码并移除 EXIF/GPS；
- 计算清理后内容 SHA-256；
- 使用账户和工单隔离的私有对象键。

补充参考图请求需要 `Idempotency-Key`。

## 管理员 API

```text
GET  /api/v1/admin/pet-asset-production-jobs
GET  /api/v1/admin/pet-asset-production-jobs/{job_id}
POST /api/v1/admin/pet-asset-production-jobs/{job_id}/assign
POST /api/v1/admin/pet-asset-production-jobs/{job_id}/update
POST /api/v1/admin/pet-asset-production-jobs/{job_id}/artifact
GET  /api/v1/admin/pet-asset-production-jobs/{job_id}/artifact/package
GET  /api/v1/admin/pet-asset-production-jobs/{job_id}/reference-images/{reference_id}/image
```

写操作需要管理员 `edit` 权限。

负责人必须是具有 `editor` 或 `superadmin` 角色的账户。产物上传仅允许当前负责人或超级管理员执行。

## 进度规则

- 进度范围为 0 到 100。
- 普通状态更新只能设置 0 到 99。
- 制作过程中进度不能倒退。
- `failed → queued` 重试会显式把进度重置为 0。
- 只有产物通过校验后，进度才设为 100。

## 产物约束

产物上传必须指定 `target_template_version_id`。

服务端会验证：

1. 目标模板版本存在；
2. 目标模板代码与工单宠物当前 `template_id` 一致；
3. 目标版本处于 `draft` 或 `changes_required`；
4. ZIP 符合大小、文件数和解压大小限制；
5. ZIP 不包含路径穿越、符号链接或加密文件；
6. Manifest 版本受支持；
7. `template_id`、`identity_version`、`asset_version` 与目标版本一致；
8. 13 种必需动作存在或有合法降级；
9. 引用图片可正常解码；
10. Spritesheet 尺寸符合声明。

校验通过后，服务端创建一条不可变 `pet_asset_production_artifacts` 记录。

每个工单只允许一个产物。再次上传会返回冲突，不会覆盖原对象。

产物显式记录：

- 工单 ID；
- 原始 submission ID；
- 目标宠物 ID；
- 目标模板版本 ID；
- 对象键；
- SHA-256；
- 文件大小；
- Manifest；
- 上传管理员和时间。

## 操作日志与同步

每次重要操作都会追加 `pet_asset_production_job_logs`：

- 工单创建；
- 分配负责人；
- 状态或进度变化；
- 用户补充参考图；
- 产物校验完成；
- 用户撤回。

用户账户会收到：

```text
pet_asset_production_job_updated
```

实时 WebSocket 仍只推送账户游标变化，客户端通过 REST 读取最新工单详情。

管理员写操作同时进入 `admin_audit_logs`。

## 后续 D3

`ready` 产物还需要：

- 独立审核；
- 制作人与审核人分离；
- 视觉身份和权利档案检查；
- 生成不可变专属 release；
- 建立单宠部署指针；
- 客户端鉴权下载；
- 兼容性检查和版本回退。
