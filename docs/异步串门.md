# 异步串门

## 目标

异步串门允许好友之间选择各自宠物建立一段有明确开始和结束时间的来访记录：

```text
好友关系
→ 选择自有来访宠物
→ 选择好友可见的接待宠物
→ 发出申请
→ 接待方接受
→ 来访宠物进入 visiting
→ 到期自动返家或主人主动召回
→ 双方保留串门摘要
```

服务端是串门状态、宠物位置和时间边界的唯一权威来源。

## 一、数据模型

串门使用独立 `pet_visits` 表，不修改既有宠物主表结构。

主要字段：

- 申请账户和接待账户；
- 来访宠物和接待宠物；
- 申请状态；
- 15～240 分钟的串门时长；
- 最多 200 字的留言；
- 接受时间、开始时间、预计返家时间和完成时间；
- 完成原因。

## 二、状态机

```text
pending
├─ accepted → active
├─ rejected
├─ cancelled
└─ 24 小时未处理 → expired

active
├─ 到期 → completed
├─ 主人召回 → recalled
├─ 屏蔽账户 → recalled
└─ 解除好友 → recalled
```

终态不会重新打开。

## 三、HTTP API

```text
POST /api/v1/visits
GET  /api/v1/visits

POST /api/v1/visits/{visit_id}/accept
POST /api/v1/visits/{visit_id}/reject
POST /api/v1/visits/{visit_id}/cancel
POST /api/v1/visits/{visit_id}/recall
```

列表响应分为：

- `incoming_requests`：收到的待处理申请；
- `outgoing_requests`：发出的待处理申请；
- `active`：正在进行的串门；
- `history`：拒绝、取消、完成、召回和过期记录。

## 四、创建规则

发起串门必须同时满足：

- 双方是好友；
- 任一方向不存在屏蔽关系；
- 申请人是来访宠物的 `owner` 或 `co_owner`；
- 接待账户是接待宠物的 `owner` 或 `co_owner`；
- 接待宠物对申请人可见；
- 两只宠物当前均为 `home` 或 `resting`；
- 来访宠物没有其他待处理或进行中的串门；
- 串门时长在 15～240 分钟之间。

接待宠物可见性会在创建和接受时各验证一次。私有宠物 ID 即使被猜到，也不能用于发起串门。

## 五、宠物位置与照料

接待方接受后：

```text
visitor_pet.presence = visiting
```

来访期间，现有照料接口会返回冲突，不能投喂、玩耍、清洁、摸摸或休息。

到期、召回、屏蔽或解除好友后：

```text
visitor_pet.presence = home
```

每次位置变化都会增加 `state_version`，并通过既有 `pet_updated` 事件同步到所有拥有该宠物关系的设备。

## 六、自动返家

当前没有常驻后台调度进程。服务端采用惰性结算：

- 查询宠物列表；
- 设备 bootstrap；
- 用户门户 dashboard；
- 查询串门列表；
- 提交宠物照料动作；

这些入口会先结算已经到期的串门，再返回或执行后续操作。因此即使客户端在到期时离线，下一次连接后仍会得到权威返家状态。

## 七、关系撤销

屏蔽账户或解除好友时：

- 双方待处理串门申请立即取消；
- 双方进行中的串门立即结束；
- 来访宠物恢复 `home`；
- 双方收到串门状态事件；
- 宠物关系账户收到新的宠物快照。

解除屏蔽或重新成为好友不会恢复旧串门。

## 八、桌面端

托盘菜单新增：

```text
异步串门…
```

桌面界面支持：

- 选择好友；
- 加载好友对当前账户可见的宠物；
- 选择 30 分钟、1 小时、2 小时或 4 小时；
- 填写可选留言；
- 发送串门申请；
- 接受、拒绝或取消申请；
- 查看正在进行的串门和预计返家时间；
- 召回自己管理的来访宠物；
- 查看历史状态与结束原因。

收到新的串门申请时，Windows 托盘会显示通知。桌面端使用已有设备令牌，不保存新的服务端密钥。

## 九、同步事件

新增语义事件：

```text
pet_visit_updated
```

宠物位置变化继续使用：

```text
pet_updated
```

串门事件包含记录 ID、双方账户、两只宠物、状态、预计结束时间和结束原因。客户端不需要根据本地时间自行推导权威状态。

## 十、安全边界

- 不能向非好友发起串门；
- 屏蔽关系优先于好友关系；
- 私有宠物不能通过猜测 ID 绕过可见性；
- 只有接待账户可以接受或拒绝；
- 只有申请账户可以取消待处理申请；
- 只有来访宠物的管理者可以召回；
- 串门不能修改成长数值、所有权、照料贡献或素材版本；
- 留言只作为普通文本保存，不执行 HTML 或脚本；
- AI 不参与串门决策、权限判断或自动操作。

## 十一、当前限制

- 当前每只来访宠物只能有一个待处理或进行中的串门；
- 每只接待宠物同一时间只接待一只来访宠物；
- 没有实时 WebSocket，PC 通过既有轮询和按需刷新获取变化；
- 用户 Web 门户尚未加入串门管理页面；
- 串门不会自动增加成长经验或生成虚拟礼物；
- 没有常驻后台任务，自动返家依赖下一次服务端请求触发惰性结算。
