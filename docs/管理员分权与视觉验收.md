# MyPets 管理员分权、视觉验收与安全回滚

## 一、目标

本阶段把管理员管理台从单一白名单升级为职责分离的内容发布平台，并强化宠物形象发布前的视觉验收能力。

核心流程：

```text
宠物编辑创建模板和版本
→ 上传并校验素材包
→ 内容审核员检查动作与形象
→ 发布管理员正式发布
→ 稳定通道自动指向新 Release
→ 异常时切回历史不可变 Release
→ 审计员查看完整操作记录
```

所有 Release 继续保持不可变。回滚只修改稳定通道指针，不覆盖、不删除历史素材。

## 二、角色与权限

| 角色 | 权限 |
|---|---|
| `editor` | 查看、创建模板和版本、上传素材、提交审核 |
| `reviewer` | 查看、批准或退回审核中的版本 |
| `publisher` | 查看、正式发布、切换稳定通道和回滚 |
| `auditor` | 查看、读取管理员审计日志 |
| `superadmin` | 拥有全部权限和后续管理权限 |

旧环境变量 `MYPETS_ADMIN_USERNAMES` 仍然可用，其中的账户按超级管理员处理。

推荐使用细分配置：

```powershell
$env:MYPETS_ADMIN_EDITORS = "pet_editor"
$env:MYPETS_ADMIN_REVIEWERS = "pet_reviewer"
$env:MYPETS_ADMIN_PUBLISHERS = "pet_publisher"
$env:MYPETS_ADMIN_AUDITORS = "pet_auditor"
$env:MYPETS_ADMIN_SUPERADMINS = "platform_admin"
```

同一个账户可以被配置到多个角色，但生产环境建议继续保持创建、审核和发布人员分离。

## 三、服务端授权

管理员 API 仍使用账户 Bearer Token。权限由服务端根据账户名和环境配置计算，浏览器不能声明或提升角色。

主要权限映射：

```text
POST 模板、版本、素材包、提交审核 → edit
POST 批准、退回                    → review
POST 发布、回滚                    → publish
GET  审计日志                      → audit
GET  模板、预览、对比、发布历史     → view
```

管理台会隐藏无权操作，但真正的授权判断始终在 FastAPI 中间件和原有业务状态机完成。

## 四、管理员身份接口

```text
GET /api/v1/admin/me
```

响应包含：

```json
{
  "account_id": "...",
  "username": "pet_editor",
  "display_name": "宠物编辑",
  "roles": ["editor"],
  "permissions": ["edit", "view"]
}
```

访问令牌只保存在浏览器 `sessionStorage`，关闭标签页或浏览器会话后失效。

## 五、连续动画验收

管理台使用现有受保护的单帧预览接口，在浏览器中按指定 FPS 顺序请求帧：

```text
4 FPS
8 FPS
12 FPS
24 FPS
```

支持：

- 播放和暂停；
- 上一帧和下一帧；
- 手动输入帧号；
- 切换动作；
- 显示原生动作与降级动作；
- 对逐帧包和精灵表使用相同预览流程。

预览图继续通过 Bearer 认证获取，并转换为浏览器临时 Blob URL。令牌不会出现在图片 URL 或浏览器历史中。

## 六、桌面尺寸模拟

视觉验收区域提供三种比例：

```text
桌面 16:9
紧凑 4:3
竖屏 9:16
```

该模拟器用于检查：

- 宠物主体占屏比例；
- 透明边距；
- 底部任务栏附近的视觉位置；
- 横屏与竖屏中的裁切风险；
- 小尺寸区域的辨识度。

它不是完整操作系统窗口模拟器，不替代 Windows 高 DPI、多显示器和实际客户端回归测试。

## 七、版本差异对比

```text
GET /api/v1/admin/pet-template-versions/compare
    ?left_id=...
    &right_id=...
```

比较内容：

- 模板是否变化；
- 渲染器配置是否变化；
- 视觉身份版本是否变化；
- 素材版本是否变化；
- ZIP 包哈希是否变化；
- 动作新增、删除和修改；
- 原生帧数变化；
- 动作降级来源变化。

版本对比只读取已经通过上传校验的 Manifest，不执行素材包中的任何代码。

## 八、稳定发布通道

新增：

```text
pet_asset_deployments
```

稳定通道记录：

```text
template_code
channel = stable
active_release_id
previous_release_id
updated_by_account_id
reason
updated_at
```

每次新的不可变 Release 发布后，稳定通道自动切换到该 Release，并保留上一个 Release ID。

公开查询：

```text
GET /api/v1/catalog/pet-assets/latest?template_id=official.cat.white
```

该接口返回当前稳定通道指向的 Release。原有按精确版本查询接口继续保留。

## 九、安全回滚

```text
POST /api/v1/admin/pet-asset-deployments/{template_code}/rollback
```

请求：

```json
{
  "release_id": "历史 Release ID",
  "reason": "高 DPI 环境出现主体裁切，恢复上一稳定版本"
}
```

约束：

1. 只有 `publisher` 或 `superadmin` 可以回滚；
2. 目标必须是同一模板的已发布 Release；
3. 不能回滚到当前已经生效的 Release；
4. 回滚不修改 Release 内容；
5. 回滚写入 `admin_audit_logs`；
6. `previous_release_id` 保存切换前的稳定版本。

回滚完成后，新客户端通过稳定目录获取目标版本。已经明确锁定精确 `asset_version` 的宠物实例不会被静默改写。

## 十、管理台表现

管理台根据当前权限动态显示：

- 编辑按钮和上传区域；
- 审核中心和审核按钮；
- 发布和回滚按钮；
- 审计日志入口；
- 当前账户角色徽章。

隐藏 UI 只用于减少误操作，不能替代服务端权限校验。

## 十一、测试门槛

必须覆盖：

- 编辑账户不能批准或发布；
- 审核账户不能创建或发布；
- 发布账户不能审核；
- 审计账户只能读取日志和查看内容；
- 超级管理员兼容旧白名单并拥有全部权限；
- 发布后稳定通道自动切换；
- 第二次发布保存上一 Release；
- 回滚后公开稳定目录返回历史 Release；
- 回滚行为进入审计日志；
- 版本对比识别动作降级和帧数变化；
- 管理台 JavaScript 通过语法检查；
- Windows、Linux 和后端现有回归继续通过。

## 十二、当前限制

尚未实现：

- 数据库管理的角色分配界面；
- 企业 SSO、OIDC 或 SAML；
- 双人发布审批；
- 灰度百分比和多发布通道；
- 自动崩溃指标触发回滚；
- 像素级双图叠加和轮廓差异热力图；
- 真机远程预览；
- 生产数据库迁移脚本和对象存储签名。
