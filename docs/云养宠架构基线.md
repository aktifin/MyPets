# MyPets 云养宠架构基线

本文档是后续产品、数据库、接口和客户端改造的统一约束。当前仓库已落地 PC 客户端领域模型分层重构（`src/onepic_desktop_pet/domain/`）、Alembic 23 张表数据库迁移管理、陪伴成长评估算法、桌面独立访客窗口（`GuestPetWindow`）与桌面实时串门。系统保持 100% 离线桌宠兼容性与安全降级。

## 产品边界

MyPets 目标能力包括：

- 一个账户拥有多只宠物；
- 一只宠物可以由多个账户共同照料；
- 宠物独立成长、独立社交和独立消息；
- PC 桌面端负责动画、低打扰消息、提醒和访客宠物；
- 小程序负责移动管理、远程投喂、好友、串门和设备控制；
- MyReminder 作为提醒数据源，MyPets 负责可靠调度和宠物化展示；
- AI 仅用于文字聊天、语音聊天、人格和用户可控记忆；
- 不建设 AI 智能体、工具执行、WorkBuddy、OpenClaw 或电脑自动操作。

## 核心主体

### 账户

账户是登录、好友、设备、隐私和用户成就主体。

### 宠物模板

管理员维护的标准角色定义，包括：

- 视觉身份；
- 成长阶段；
- 动作能力；
- PC 与小程序素材；
- AI 聊天人格；
- 版权、审核和版本信息。

### 宠物实例

用户实际养育的具体宠物。实例记录模板及形象版本，模板更新不能无确认地改变用户宠物身份。

## 状态权威

云端上线后，以下数据以服务端为准：

- 成长经验和阶段；
- 饱食度、精力、心情、清洁度和健康度；
- 账户与宠物角色；
- 好友、串门和聚会状态；
- 消息已读状态；
- 提醒实例状态。

PC 客户端负责动画和离线缓存，不自行决定云端业务结果。

## 语义事件

云端只同步语义事件，不同步动画帧和实时像素坐标。

事件统一包含：

```text
event_id
sequence_number
idempotency_key
created_at
target_account_id
target_device_id
payload
```

典型事件：

```text
pet_stats_changed
growth_stage_changed
message_received
visit_started
visit_returned
gathering_action_started
reminder_due
asset_version_changed
```

## PC 边缘半隐藏

当前已落地左右边缘模式：

- 拖到边缘后自动吸附；
- 延迟滑入并保留可见部分；
- 鼠标进入后展开；
- 拖离后解除吸附并恢复原跑动设置；
- 按显示器名称和纵向比例恢复；
- 托盘可手动吸附、展开和解除。

底部任务栏和顶部边缘暂不参与吸附。


管理员或素材制作者可以运行：

```powershell

```

校验内容包括：

- 基础动作完整性；
- 动作降级；
- 走路位移曲线；
- 边缘可见比例；
- 视觉边界；
- 素材路径越界和缺失。

## 消息与提醒

消息和提醒必须使用不同入口：

```text
💬 宠物与好友消息
⏰ 待处理提醒
```

消息默认折叠、不抢焦点、不直接显示正文。提醒可以完成、忽略和贪睡，读取不等于完成。

MyReminder 接入不得直接读取其 JSON 数据文件，应通过受限 API 同步提醒定义和提醒实例。

## 串门与聚会

宠物位置状态：

```text
HOME
PREPARING
TRAVELLING
VISITING
GATHERING
RETURNING
RESTING
```

实时串门使用独立 `GuestPetWindow`。访客宠物不得读取本机提醒、私密聊天、麦克风或文件。

多宠物聚会由场景协调器分配站位和动作，不建设实时物理世界。动作缺失按 Manifest 降级。

## AI 交流边界

AI 允许输出：

```text
text
emotion
animation_hint
voice_style
display_mode
memory_candidates
```

AI 禁止输出或执行：

```text
tool_call
file_operation
browser_action
reminder_operation
message_send
visit_operation
device_control
```

提醒、串门、消息和设备控制均通过确定性界面与业务服务完成。

## 管理员内容平台

管理员平台负责：

- 宠物模板创建；
- 视觉身份档案；
- 成长与动作配置；
- PC 和小程序素材；
- AI 聊天人格；
- 版权来源；
- 自动校验；
- 双端预览；
- 审核、灰度、发布和回滚。

创建、审核和发布权限应分离。已发布版本不可覆盖，只能创建新版本。
