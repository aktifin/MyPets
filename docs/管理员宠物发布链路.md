# MyPets 管理员宠物模板与形象包发布链路

## 当前范围

本阶段把宠物模板、模板版本、素材审核、不可变发布和桌面下载串成可运行闭环：

```text
管理员创建模板
→ 创建模板版本
→ 上传 ZIP 形象包
→ 服务端结构与图片校验
→ 提交审核
→ 另一名管理员批准
→ 发布不可变 Release
→ PC 查询公开目录
→ 校验大小和 SHA-256
→ 原子安装到版本缓存
→ 热切换形象
```

AI 仍只用于聊天，不参与模板审核、发布或素材执行。

## 管理员配置

管理员权限采用服务端用户名白名单，不由客户端声明：

```powershell
$env:MYPETS_ADMIN_USERNAMES = "pet_editor,pet_reviewer"
$env:MYPETS_ASSET_STORAGE_DIR = "D:\MyPetsData\assets"
```

用户名会规范化为小写。未配置白名单时，所有管理员接口均拒绝访问。

开发环境使用 `FileObjectStore`。生产环境应替换为 S3 兼容对象存储和 CDN，但数据库中的 `object_key`、SHA-256、大小及发布 ID 保持不变。

## 数据模型

```text
pet_templates
pet_template_versions
pet_asset_releases
admin_audit_logs
```

模板版本状态：

```text
draft
in_review
changes_required
approved
published
```

已发布版本不能替换素材包。新视觉内容必须创建新版本。

## 管理 API

所有管理接口要求账户访问令牌，并要求账户名位于 `MYPETS_ADMIN_USERNAMES`。

```text
POST /api/v1/admin/pet-templates
GET  /api/v1/admin/pet-templates

POST /api/v1/admin/pet-templates/{template_id}/versions
GET  /api/v1/admin/pet-templates/{template_id}/versions
GET  /api/v1/admin/pet-template-versions/{version_id}

POST /api/v1/admin/pet-template-versions/{version_id}/package
POST /api/v1/admin/pet-template-versions/{version_id}/submit-review
POST /api/v1/admin/pet-template-versions/{version_id}/approve
POST /api/v1/admin/pet-template-versions/{version_id}/reject
POST /api/v1/admin/pet-template-versions/{version_id}/publish

GET  /api/v1/admin/audit-logs
```

素材上传使用 `multipart/form-data`，字段名为 `package`。

## 双人审核

创建模板版本的管理员不能批准自己的版本。批准必须由另一名管理员完成。

拒绝后状态变为 `changes_required`，允许重新上传素材包并再次提交审核。发布只接受 `approved` 状态。

## ZIP 包规范

ZIP 根目录必须包含：

```text
manifest.json
```

Manifest 必须使用 2.0 或 2.1，并与模板版本中的以下字段完全一致：

```text
template_id
identity_version
asset_version
```

服务端拒绝：

- 绝对路径、`..` 路径和驱动器路径；
- 重复路径；
- 加密文件；
- 符号链接；
- 超出文件数量、压缩大小或解压大小限制的包；
- 缺少必需动作且没有降级规则的包；
- 动作降级循环；
- 精灵表坐标或尺寸错误；
- 无法解码的 PNG、WebP、JPG、JPEG；
- `files` 中大小或 SHA-256 不一致的文件。

相关限制由以下环境变量控制：

```text
MYPETS_MAX_ASSET_PACKAGE_BYTES
MYPETS_MAX_ASSET_UNCOMPRESSED_BYTES
MYPETS_MAX_ASSET_FILES
```

## 发布与公开目录

发布后生成不可变 Release：

```text
GET /api/v1/catalog/pet-assets
    ?template_id=official.cat.white
    &identity_version=1.0.0
    &asset_version=2.0.0
```

响应包含：

```text
release_id
模板和版本三元组
package_sha256
package_size
download_url
manifest
published_at
```

下载接口：

```text
GET /api/v1/assets/releases/{release_id}/package
```

响应带有长期不可变缓存头和 ETag。

## PC 自动下载

PC 发现当前云端宠物缺少精确形象版本时：

1. 查询公开目录；
2. 只接受同源 `/api/v1/assets/releases/...` 下载地址；
3. 下载 ZIP；
4. 检查字节数和 SHA-256；
5. 拒绝 ZIP 路径逃逸、加密文件和符号链接；
6. 调用现有 `PetAssetCatalog.install_package()`；
7. 完整验证成功后原子替换版本缓存；
8. 当前宠物匹配时立即热切换。

下载或安装失败时，窗口继续显示原形象或公开兼容形象。

## 审计

以下操作写入 `admin_audit_logs`：

```text
模板创建
模板版本创建
素材包上传
提交审核
批准或退回
正式发布
```

日志记录操作账户、资源类型、资源 ID、动作、结构化详情和时间。
